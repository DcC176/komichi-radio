# 第三方云托管部署指南（腾讯云 / 阿里云）

适用对象：`cloud/` 这个包（纯 Python 标准库 + 静态站点，单端口，无数据库）。
本目录下的脚本也可用于任何 Linux 主机（Oracle Cloud、家庭服务器、其他厂商 VPS 同理）。

---

## 0. 结论

**选型判据只有一条：带宽。** 本项目是视频中转，每个 480P 观众约占 1 Mbps；
CPU 与内存几乎不构成约束（Python 单进程，常驻 30–60 MB）。所以：

| 使用场景 | 推荐 | 首年成本 |
|---|---|---|
| **对外公开**（并发 >10 人） | 200 Mbps 峰值带宽套餐 | 阿里云「高带宽专区」**68 元/年**（首年活动价，续费价需核对）；或腾讯云轻量「锐驰型」45 元/月（标准价，无活动依赖） |
| **自用 / 小圈子**（并发 ≤6 人） | 固定带宽 5–6 Mbps 套餐 | 腾讯云轻量 2 核 4G / 6M / 600 GB **199 元/年**（1 年续费同价） |

其余三条前提：

1. **不绑域名就不涉及备案**，可以当天上线（用 `http://<公网IP>:8080` 直接访问）。
2. 裸机 + systemd 即可，不需要 Docker —— 本服务无第三方依赖、单进程、无状态，
   容器带来的隔离收益很小，却要多维护一整套运行时。
3. 两年前那套「按 GB 计费 + 2 Mbps 带宽」的入门型套餐（35 元/月、100 GB）
   对本项目**完全不可用**：100 GB 约等于 220 小时观看，而 2 Mbps 只能同时
   支撑 2 个 480P 观众。

> 活动价时效性很强（见 §1.1），**下单前务必在控制台核对续费价** ——
> 「首年 68 元、次年 1000+ 元」是这类秒杀套餐的常态。

## 2. 成本结构

| 项 | 本项目实际情况 |
|---|---|
| 计算 | 极低。Python 单进程，常驻内存约 30–60 MB，2 核 2G 属于大幅冗余 |
| 磁盘 | 极低。`cloud/` 整包约 2.1 MB |
| **出口流量** | **唯一的成本变量**。视频流经服务器中转，480P 约 1 Mbps ≈ 450 MB/小时/人 |
| 入口流量 | 通常免费 |

按「无限流量」套餐计，日常成本就是**固定的 45 元/月**。
按传统「流量包」套餐计，1 TB 约等于 2 200 小时观看，超出后约 0.8 元/GB ——
这正是**必须避开入门型套餐**的原因。

## 3. 三个必须知道的风险

### 3.1 B 站风控（技术风险，最大）

云服务器的 IP 属于**数据中心 IP**，B 站对这类 IP 有风控。
WorkBuddy 托管环境（新加坡节点）上实测：`x/web-interface/view` 返回 **412**，
而 `x/series/archives`、`x/player/pagelist`、`x/web-interface/wbi/view` 仍是 200。

服务内已有四路回退（`view → wbi/view → view/detail → pagelist`），
所以**风控通常不会导致功能失效**，但**必须实测确认**：

```bash
bash deploy/selfcheck.sh http://<公网IP>:8080
```

第 3 节会打印每个接口的真实 HTTP 码。只要「实时节目单」一项通过，播放链路就成立。
如果全部被拦，退路是换地域（如中国香港/新加坡节点，风控策略不同），或改用
`../直播回放24h频道-决策补充与方案修订.md` §4 的官方嵌入播放器方案（不需要服务器）。

### 3.2 峰值带宽不是承诺带宽

两家的官方文档都写明：**峰值带宽不作为业务承诺指标，高峰期资源争抢时可能被限制**。
200 Mbps 是上限而非保底。对「几个朋友一起看」的规模完全够用；
若要办「公开大规模观看」，需要 CVM/ECS 的固定带宽或 CDN，成本量级完全不同。

### 3.3 合规与账号风险

本项目是粉丝向二创站点，采用**服务端中转视频流**的形态。按
`../直播回放24h频道-决策补充与方案修订.md` §2 的分级，这属于**高风险动作**
（转发视频流本身即是风险主要来源），且放在国内云厂商平台上，
一旦被投诉，处置会直接落到你的云账号上。

降低风险的最低成本动作（详见该文档 §2）：
- 页面显著位置标注「非官方粉丝站」，版权归 UP 主 **四时小路Komichi** 所有；
- 每个节目提供指向 B 站原视频的链接；
- 不投广告、不收费、不做下载；
- 留联系渠道，收到通知立即下架；
- **向 UP 主本人说明并取得默许** —— 成本最低、效果最好的一步。

此外建议**给站点加访问控制**（见 §4.4），避免变成任何人可用的公开转发器。

## 4. 部署

### 4.1 购买服务器

腾讯云控制台 → 轻量应用服务器 → 新建：
- 地域：**中国内地**（上海 / 广州，离你和观众近）
- 镜像：**系统镜像 → Ubuntu 22.04 LTS**（不要选应用镜像，不需要）
- 套餐：**锐驰型 2 核 2G**（45 元/月）
- 时长：先买 1 个月试

创建完成后，在实例详情的**防火墙**里放行 **TCP 8080**（默认只开了 22/80/443）。
这一步漏了会导致「部署成功但外网打不开」。

### 4.2 一键推送部署

在你本机（项目根 `小路回放台/`）执行：

```bash
bash deploy/push.sh --target root@<公网IP>
```

它会用 tar 管道把 `cloud/` 与 `deploy/` 传到服务器 `/opt/komichi-radio/`，
然后在服务器上执行 `deploy.sh`：建系统账号、装 systemd 服务、启动、自检。

- 腾讯云 Ubuntu 镜像默认登录用户是 `ubuntu`，则需要 `--target ubuntu@<IP>`，
  并保证该用户能 `sudo`；用密钥登录时加 `--key ~/.ssh/xxx.pem`。
- 阿里云默认 `root`，直接 `--target root@<IP>`。

**也可以不用这个脚本**，手动上传后执行：

```bash
scp -r cloud deploy .dockerignore root@<IP>:/opt/komichi-radio/
ssh root@<IP> "cd /opt/komichi-radio && bash deploy/deploy.sh"
```

### 4.3 验证

部署脚本最后会自动跑自检。任何时候都可以单独跑：

```bash
bash deploy/selfcheck.sh http://<公网IP>:8080
```

期望输出：`通过 7 项，失败 0 项 / 结论：部署成功，服务可用。`

浏览器打开 `http://<公网IP>:8080` 应看到节目单；点播放能出画面即完整打通。

### 4.4 绑域名 + HTTPS + 访问控制（可选）

需要满足三个前提：有域名、**完成 ICP 备案**（国内地域必须）、能接受 1–20 天等待期。

```bash
# 1. 装 nginx 与证书工具
sudo apt update && sudo apt install -y nginx certbot python3-certbot-nginx

# 2. 把域名解析到公网 IP 后，签证书
sudo certbot --nginx -d radio.example.com

# 3. 装入反代配置（先编辑里面的域名）
sudo cp deploy/nginx-komichi.conf /etc/nginx/conf.d/komichi-radio.conf
sudo nginx -t && sudo systemctl reload nginx
```

`deploy/nginx-komichi.conf` 里已包含两处关键配置，不要删：
- `proxy_set_header X-Forwarded-Host $host;` —— 服务靠它生成 MPD 里的正确地址，删了会播放失败；
- `proxy_buffering off;` —— 不关会导致拖进度卡顿。

同一文件里还预留了 **Basic 密码保护**与 **IP 白名单**两段（默认注释掉），
建议至少启用一段。启用后部署时记得把域名写进 CORS 白名单：

```bash
sudo bash deploy/deploy.sh --host radio.example.com
```

## 5. 日常运维

```bash
# 看日志
journalctl -u komichi-radio -f

# 重启 / 停止
systemctl restart komichi-radio
systemctl stop komichi-radio

# 更新代码（改完 cloud/ 后在本地重推一次即可）
bash deploy/push.sh --target root@<IP>

# 只做自检，不改动系统
bash deploy/deploy.sh --check
```

改端口：`sudo bash deploy/deploy.sh --port 9000`，同时别忘了在云控制台防火墙放行新端口。

## 6. 与 WorkBuddy 托管版的差异

| 项 | WorkBuddy「发布为应用」 | 第三方云（本文方案） |
|---|---|---|
| 链接 | **每次发布都换一个随机域名**，旧链接立即失效 | 固定 IP / 自有域名，永久有效 |
| 可读域名 | 做不到（`domainPrefix` 参数无效，实测） | 可绑自有域名 |
| 成本 | 走平台额度 | 45 元/月 |
| 带宽 | 平台额度 | 200 Mbps 峰值（非承诺） |
| 运维 | 无 | 需要自己管 systemd、防火墙、续费 |
| 出口 IP | 新加坡 | 可自选中国内地 |
| 凭据 | 同样不存任何登录态 | 同 |

**结论：如果在意「链接稳定、可绑域名、国内访问快」，迁到第三方云是正确选择；
如果只是临时分享，WorkBuddy 托管更省事。**
